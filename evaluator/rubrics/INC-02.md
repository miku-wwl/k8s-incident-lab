# Owner 私有评分细则 — INC-02

## 标准答案（Ground Truth）

- 根因：同步请求并发超过 Gateway 的有效处理槽位，而较大的 CPU request 让基于利用率的 HPA 信号低估饱和程度。
- 触发因素：代表性需求窗口显著提高并发与到达速率。
- 促成因素：伸缩指标没有表达排队、拒绝和有效并发容量。

## 期望证据

- 请求量、5xx 和 p95 上升，日志出现并发拒绝。
- HPA 仍接近最小副本，CPU 利用率百分比没有对应客户影响。
- Pod 大多 Running，依赖不需要同时失败。

## 可接受缓解

- 降低进入流量，或扩展真正有效的 Gateway 容量并验证错误率下降。

## 常见错误假设

- 仅因为 CPU 不高就排除容量问题；盲目提高 CPU limit 而不验证并发瓶颈。

## 纠正措施方向

- 使用并发、排队或拒绝指标伸缩；校准 requests；增加容量压测和过载保护。
