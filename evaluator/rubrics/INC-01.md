# Owner 私有评分细则 — INC-01

## 标准答案（Ground Truth）

- 根因：Gateway `2.0.0` 版本把下游客户端超时缩短到低于 Catalog 正常依赖链延迟。
- 触发因素：常规发布将 Gateway 镜像从 `1.0.0` 更新到 `2.0.0`。
- 促成因素：就绪探针只验证本地进程；发布门没有覆盖真实下游路径延迟。

## 期望证据

- 发布历史、镜像版本和 change-cause 与退化时间一致。
- Gateway 仍 Available，但 5xx、p95 和依赖超时日志上升。
- Catalog/Identity 直接路径仍可用。

## 可接受缓解

- 回滚 Gateway 到已知健康版本，或恢复经过验证的客户端超时配置。
- 必须验证 Gateway 客户路径、错误率和延迟恢复。

## 常见错误假设

- Gateway Pod 崩溃、集群整体容量不足、Catalog 完全不可用。

## 纠正措施方向

- 发布前依赖链 SLO 测试、超时预算评审、症状型金丝雀门和自动回滚。
